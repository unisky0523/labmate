## 2. 正式组别与规则

对应组别为第 3.3 节“自主选题赛道（初级组）”，并非第 3.1 节 RTL/HLS 本地智能体设计赛道或第 3.2 节具身智能赛道。

| 核查事项 | 指南已明确的要求 | 对 LabMate 的影响 |
| --- | --- | --- |
| 初级组资格 | 大学一年级至三年级在读本科生；混合年级、学历的队伍按最高者划分 | 需要按报名截止时的实际身份核对队员资格，不能只看队长年级 |
| 允许器件 | AMD 7 Series、Zynq-7000、UltraScale、UltraScale+ | 当前记录中的 Zynq-7010 属于允许系列；交付时仍须核实并声明具体芯片型号 |
| 组别考察侧重 | 逻辑设计、状态机、时序约束、接口协议等基本 FPGA 设计能力 | 不能只证明 ARM 软件能运行，还需要能说明队伍掌握的硬件设计与验证内容 |
| 实现方式 | RTL、Vitis HLS、AI Engine、PS 软件及其组合均可 | PS 软件是合法且有价值的实现部分；指南没有给出最低 PL 占比，也没有写“纯 PS 自动取消资格” |
| 作品价值 | 可以体现在硬件加速、系统集成、接口设计或应用创新 | 不必把整套 Vosk 搬到 PL；可以选择一个实际有价值的硬件模块完成软硬件协同 |
| PYNQ | 推荐，非唯一实现方式；通用 PYNQ Skill 可另行加分 | 不应仅为推荐路线立即重装已有 Linux；具体加分上限、分档和是否突破 100 分未在指南中列出 |
| 工具 | 推荐 Vivado/Vitis 2026.1，亦列出 2025.2；其他版本需在报告说明并保证脚本复现 | 先核对实际工程版本，再判断是否需要迁移；板上 Linux 的 2020.2 标签不能直接等同于实际构建工具版本 |
| 板级验证 | 须在实际可获取的器件上跑通并提供实测输出 | 仿真、PC 单元测试、软件界面截图均不能替代真实板级结果 |
| 开源 | 指南用语为“强烈要求”在 GitHub/Gitee 开源，并采用允许再分发的协议，推荐 MIT/Apache-2.0 | 准备可公开、可构建的交付工程，标明厂商例程和第三方组件来源 |

PS 负责窗口、Vosk 和业务流程，仍然是合理分工。需要调整的是项目主线和证据，而不是强行把窗口或整个中文识别引擎写成 RTL。

- [main.py](D:/labmate_b/main.py)：统一写记录和来源标记等逻辑有价值；默认读数仍可来自 mock，演示和报告必须区分真实采集与模拟值。
- [README_board.md](D:/labmate_b/README_board.md)：记录了同一段语音通用识别 25.62 秒、命令词表 2.66 秒的对照，也保留了音频听感异常尚未完全确认解决的说明。

必须保持以下归因：

1. Zynq 板上运行 Python/Vosk，属于 PS 侧嵌入式实现。
2. 调用厂商已提供的音视频逻辑，属于平台集成；需声明复用来源与队伍修改范围。
3. 新增屏幕按钮和开机运行改善完整性，但不自动产生自研 PL 设计成果。
4. 词表模式的识别提速属于软件解码范围改变，不能写成 FPGA 硬件加速。
5. 自研硬件贡献要对应可交付源码、接口、验证结果、实现报告和真实系统调用。

结论：实验助手这个应用方向可以保留，已有 PS 原型也可以复用。当前参赛竞争力的主要缺口是可解释、可验证的自研硬件贡献与真实业务闭环；不应继续把主要精力全部投入界面美化、词表无限扩充或微调启动延时。

## 5. 建议的软硬件划分与 PL 选题

建议保留 PS 负责：Vosk、中文命令解析、状态机、确认/取消、界面、存储和异常提示。

PL 阶段选择与真实任务相关、能独立验证、能接入现有工程的模块。实际选择以 PS 基线的耗时和数据通路测量为依据，不提前认定某个环节必然适合硬件加速。针对当前摄像头和仪表读数方向，可评估在厂商视频例程上增加自研图像预处理模块，例如：

`真实图像/ROI -> 定点灰度处理 -> 可调阈值二值化 -> 行列投影/候选数字区域统计 -> PS 数字识别与来源核对`

这是一项待工程确认的设计建议，不是已经选定的现有实现。先检查厂商工程、视频格式、数据接口、时钟复位和可用资源；不要假设当前摄像头数据能直接接入任意 AXI-Stream IP。可根据现有工程选择视频流接入或 PS 缓冲区搬运。

该模块应至少形成以下成果：

- 原创 RTL 或 HLS 源码，并清楚标注复用 IP。
- 明确的像素格式、图像尺寸、位宽、饱和/截断规则和边界行为。
- 参数及状态接口，例如 ROI、阈值、完成标记和错误状态。
- 含异常输入、帧边界、复位和必要握手/背压情形的验证。
- 与软件参考实现的逐像素或逐统计量比对。
- 综合、实现、约束与资源报告，确认目标时钟下的时序状态。
- 实际调用该模块完成一项仪表任务的板级演示。
- 与 PS 基线的公平对比，既报告计算模块，也报告包含搬运和同步的总耗时。

如果目前无法获取或重建视频工程，则再评估音频定点滤波、降采样或特征提取模块。音频路线须先确认现有采集链的可接入位置；不能为了增加一个 IP，把 16 kHz 下 CPU 原本很轻的能量统计搬到 PL 后就预设系统一定更快。DMA、缓存和同步开销必须计入对比。

在当前阶段不建议把完整 Vosk 移植到 PL、从零训练中文大模型，或同时开设多个互不依赖的新硬件模块。先做成一个真实有用的自研模块，比增加未完成分支更利于完整性与复现。

## 6. 建议的测量口径（不是官方分档）

| 证据 | 建议方法 | 需要避免的误读 |
| --- | --- | --- |
| 语音命令效果 | 固定独立测试集，覆盖不同说话人、数字、单位、噪声与无关语句；保留原录音和逐条结果 | 训练/调词表用过的少量样本不能充当独立总体准确率 |
| 数值正确性 | 分别核对量名、正负号、小数位和单位；错误不能仅由“意图命中”掩盖 | 能识别“记录”不等于记录数值正确 |
| 界面响应 | 分开记录按钮到有效录音、说话结束到结果、结果到保存完成 | 将取消固定录音等待带来的收益写成识别计算加速 |
| PL 正确性 | 相同输入与软件黄金参考比对；说明定点误差和边界条件 | 只看屏幕上有图或单次成功 |
| PL 性能 | 同功能、同输入、合理优化的 PS 基线；分别报告内核和含搬运的耗时 | 使用故意低效的纯 Python 循环制造速度差；只报告 IP 内部周期 |
| 系统贡献 | 原流程总耗时与加入 PL 后的总耗时、CPU 负载、持续吞吐或任务成功率 | 将局部 10 倍提速宣传为整个系统 10 倍 |
| 资源与时序 | 实现后的 LUT、FF、BRAM、DSP、工作时钟和 WNS/TNS，注明器件及工具版本 | 把 HLS 估计值、目标时钟或仿真值冒充上板实测 |
| 完整任务 | 真实读数、识别、确认、显示、保存、追溯与取消/失败恢复 | 用 mock 成功替代真实仪器任务闭环 |
| 复现与技能包 | 从干净目录构建和部署；用另一份输入或另一个适用场景验证脚本 | 只有聊天截图、没有可运行脚本与适用边界 |

## 7. 接下来按顺序完成的工作

1. 先在目标板 PS 上分别跑通语音和图像识别，保留现有厂商底层工程；记录真实输入、预处理、中间结果、最终输出及分段耗时。暂不新增或修改 PL 加速逻辑。
2. 将两个 PS 流程接入一个最小真实实验任务，包含必要的显示、确认/取消和记录功能；区分真实采集与 mock。收齐板卡型号、厂商原始工程、已有修改、工具版本、bitstream/XSA 和启动配置，作为后续迁移的准备材料。
3. 固定可运行的 PS 软件基线、模型、参数和独立测试集。以正确性和耗时测量确定 PL 候选；不等待所有界面美化或所有语句识别完美才进入下一阶段。
4. 再在可重建的厂商工程上实现选定的自研 PL 模块，依次完成接口约定、软件参考比对、仿真、综合实现和上板接入，保留 PS 实现供对照与回退。
5. 用同一块板、同一组输入、相同高层算法配置比较 PS 与 PS+PL；计入搬运、同步和驱动开销，报告局部收益与整机收益。软件词表或录音流程优化的收益单独归因。
6. 将已有采样格式诊断、ARM 部署、黄金参考比较、资源报告采集等实际经验整理成通用技能包，并附大模型协作与纠错证据。通用技能包可以基于当前 Linux 工程形成；PYNQ 专项加分另行评估。
7. 准备提交工程、报告、演示视频和决赛英文海报；按官网公布的提交时点预留打包与复现时间，并为基础 FPGA 编程能力考核留出训练时间。

指南推荐提交结构为 src/、sim/、build/、board/、data/、skill/、report/，并要求目录及文件使用英文命名，避免中文、空格及特殊字符。当前带空格的开发路径可以继续用于开发，最终另建符合要求的干净交付目录，不为整理材料而破坏现有工作区。

## 8. 本轮判定

- 应用方向：保留实验助手，强调真实实验记录、离线处理、数据来源核对和错误追溯的实际收益。
- 软件工作：保留已做的 PS 原型，它支撑完整性，但应明确其归属。
- 硬件工作：从“主要使用厂商例程”推进到“有一个队伍自研、经过验证并被系统实际调用的 PL 模块”。这属于我们基于考察侧重提出的项目建议，不是指南另设的 PL 数量门槛。
- 给分判断：正式已知的是 30/20/20/15/15；没有证据支持更细的官方分档、PL 最低占比或 PYNQ 具体加分数。本轮不作分数预测。
- 近期优先级：先完成目标板 PS 上的语音、图像和最小真实任务基线，并同步保留后续硬件工程所需材料；以实际测量决定迁移任务，随后完成自研 PL 及公平对照。当前不提前开展 PL 加速实现。
