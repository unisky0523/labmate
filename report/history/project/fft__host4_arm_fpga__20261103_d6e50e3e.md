# FFT 频谱分析：HOST4、ARM 与 FPGA 对接方案

日期：2026-11-03（北京时间）。本文保留为早期草案；实现、冻结的应用协议和验收记录请看 [FFT_ARM端交接与FPGA接口_20261103.md](FFT_ARM端交接与FPGA接口_20261103.md)。

## 1. 本轮确定的需求

- 分析 SDS1202X 示波器当前波形对应的采样数据。
- 示波器继续使用板卡原来的 **USB HOST4**；不增加触发线、不改接其他接口。
- ARM/PS 负责语音指令、通过 HOST4 读取波形、向 PL 提交数据、接收结果、绘制和保存频谱。
- FPGA/PL 负责 FFT 分析；由负责 FPGA 的队员实现计算模块及硬件接口。
- 第一版做 CH1 单通道、单次分析；后续再扩展通道选择或连续刷新。

HOST4 是板卡 USB 插口；CH1 是示波器测量通道。发生器的 HOST2 和 CH2 仍按现有分工使用，它们与上述编号独立。一次 FFT 分析不需要重新设置信号发生器。

## 3. 一次分析的完整流程

```text
“FFT 分析” / “频谱分析”
        ↓
ARM：解析为 fft_analyze，读取分析配置
        ↓
ARM ── 原有 HOST4 / USB 通信命令 ──→ SDS1202X
        ←── 波形二进制数据 + 本次记录的采样与标定参数
        ↓
ARM：校验、解包、整理采样点，放入 DMA 缓冲
        ↓
DDR → AXI DMA → PL：去直流（可选）→ 加窗 → FFT → 功率计算
        ↓
PL → AXI DMA → DDR
        ↓
ARM：校验完成状态，换算坐标与幅值，Qt 绘制频谱
        ↓
按现有保存操作归档本次原始数据、配置和结果
```

这里“给示波器一个信号”就是 ARM 经 HOST4 发通信命令。PL 不负责 USB 枚举，也不解析示波器协议。推荐通过 AXI DMA 搬运 PS/PL 数据，控制和状态使用 AXI4-Lite；这是建议新增的结构，不是已经存在的接口。

按现有读取类动作的交互方式，识别后可先分析并显示；用户确认保存时归档这一份结果，避免保存时重新采集另一帧。

## 4. HOST4 取点需要补什么

仪器通信模块增加 `scope.acquire_waveform` 能力，返回采样数据及元数据，而不是图片。

一次操作应在同一示波器访问锁内完成：

1. 核对设备身份，记录原来的运行/停止状态及需要临时修改的传输设置。
2. 锁定当前采集记录，再读取波形及相应参数。具体停止、状态确认和恢复顺序按本机固件联调。
3. 获取通道、实际点数、有效采样间隔、时间起点、电压换算参数、探头倍率及必要的采集设置。
4. 完整读取二进制块，检查声明长度、实际长度和数据编码。
5. 完成读取后按原状态恢复采集；原先已经停止时保持停止。恢复失败要单独报告。

SIGLENT 编程手册提供 `WF?`、`WFSU`、`SARA?`、`SANU?` 等波形及采样相关命令。需在当前 SDS1202X 和固件上验证具体组合、响应前缀、编码及标定公式，不能直接复制其他品牌的 `:WAV:DATA?` 实现。

注意事项：

- 波形二进制数据可以包含换行字节，不能按普通文本行读取或用固定字节数盲切头尾。
- 本次标定参数必须对应本次锁定的记录，避免在运行采集中分别读取后发生错配。
- 明确分析的是当前可见时间段还是整段存储记录。第一版在结果页显示实际分析区间；只取其中 4096 点时不能标为整屏分析。
- 首版优先使用连续、均匀的真实采样点。涉及稀疏抽点、插值或重采样时，需要核实有效采样间隔；降采样还需处理抗混叠。
- 普通“读取数据”、截图和 FFT 取点共享示波器访问调度，不能交叉发送命令和读取响应。

## 5. ARM 与 FPGA 的分工

| ARM / PS | FPGA / PL |
| --- | --- |
| 识别“FFT 分析”，管理任务状态 | 接收统一格式的采样块 |
| HOST4 通信、二进制解包、保存采集元数据 | 按配置去直流、加窗 |
| 校验数据、准备和提交 DMA 缓冲 | FFT 变换 |
| 等待完成、处理超时、关联任务编号 | 计算各频点功率 `Re² + Im²` |
| 根据采样间隔生成频率坐标 | 返回频谱、缩放信息和错误状态 |
| 幅值标定、单位换算、Qt 绘图和归档 | 如需要，后续增加峰值搜索等计算 |

ARM 根据 PL 返回的功率开方、标定幅值或转换显示单位，属于显示处理；主运行路径的 FFT 在 PL 完成。软件 FFT 仅用于离线对照验证，需清楚标注来源。

## 6. 建议先约定的接口

以下参数供双方确定，尚未冻结成硬件协议：

| 项目 | 首版建议 |
| --- | --- |
| 任务方式 | 一次提交一个采样块，完成后再提交下一块 |
| 通道 | 示波器 CH1 |
| FFT 点数 | 先以 4096 点联调；结合采样时窗和 Zynq-7010 资源决定是否调整 |
| 应用层输入 | 有符号 `int16` 采样码值，小端；原始编码在 ARM 解包后转换 |
| 输入标定 | ARM 保留 `V = gain × code + offset` 的实际参数；不对每帧自动归一化后丢失幅值比例 |
| DMA 打包 | 双方写明流位宽、每拍样本排列、实虚部位置；实数输入的虚部补零 |
| 预处理 | 可选去均值，Hann 窗；窗口定义、系数和定点舍入方式一致 |
| 输出顺序 | 自然频率顺序；若 IP 输出为位反序，由 PL 包装层重排或明确返回索引 |
| 输出数据 | 建议返回非负频率部分功率；4096 点对应 `k=0…2048`，共 2049 点 |
| 功率类型 | 建议 `uint64`，但最终位宽须由 FFT 实虚部位宽及缩放计算确认 |
| 数值说明 | FFT 总缩放量/块指数、功率计算的额外移位、窗口系数归一化方式 |
| 状态 | `idle / busy / done / error`，包含帧错误及实际可检测的数值溢出标志 |
| 关联 | 任务编号、实际输入点数、输出点数、协议版本 |
| 控制 | 配置、提交、完成通知、超时终止、恢复；寄存器偏移和地址由硬件工程给出 |

FPGA 只计算各频点功率时，不必知道采样率；ARM 必须保存对应记录的采样间隔，用于画横轴。若后续 FPGA 直接返回峰值频率，再给它相应参数。

Linux 联调还需明确负责人：设备树、DMA 驱动、缓冲分配、缓存同步、中断及用户态封装必须一起交付。不能把普通 Python 数组的虚拟地址直接当成 DMA 地址。接收缓冲应先准备好，再开始发送；`TLAST`、接收长度及实际输出点数需要一致。若只返回半谱，PL 仍须正确接收和处理 FFT 的完整输出帧。

AMD FFT 的块浮点模式会通过 `BLK_EXP` 报告变换缩放量；其他数值模式也必须给出可还原的比例说明。ARM 不能将原始整数功率直接标成伏或 dB。

## 7. 频谱图的含义与首版显示

设有效采样间隔为 `dt`，采样率为 `Fs = 1/dt`，FFT 点数为 `N`：

```text
第 k 个频点：f[k] = k × Fs / N
频点间距：Δf = Fs / N
分析时窗长度：T = N / Fs
实数单边频谱范围：0 到 Fs/2
```

例如有效采样率是 100 kSa/s、N=4096，频点间距约为 24.414 Hz，分析时窗约为 40.96 ms，单边频谱到 50 kHz。这里是参数示例，不是本轮已读取到的示波器设置。

不能直接采用示波器最高采样率：1 GSa/s 配合 4096 点，频点间距约 244.14 kHz，不适合观察 1 kHz 附近的细节。要让分析窗口覆盖足够信号周期，再选择采样设置和点数。补零可增加显示插值点，不能增加原始记录的信息量或替代更长观测时间。

首版界面建议显示：

- 频谱曲线：横轴 Hz/kHz，纵轴采用明确标注的单边幅度 Vpeak。
- 来源 SDS1202X/CH1、分析时间段、有效采样率、N、窗口、去直流选项、PL 计算状态。
- 主峰频点与频率估计，以及削顶、数据不足、计算失败等状态。

幅度换算需补偿窗口增益、FFT 定点缩放和单边谱系数；DC 与 Nyquist 点不乘 2。验证时先使用落在频点中心的正弦波核对幅值。非整周期信号还需说明峰值插值或邻近频点处理，不能保证任意单个最大频点就是精确幅值。

首版先统一 Vpeak 标尺；若增加 Vrms、dBV、功率谱密度，应分别定义，避免同一数组换个标题就当成另一种测量量。

## 9. 开发顺序与验收

1. **先拿到真实采样点。** 经 HOST4 导出一份固定记录，恢复时域波形，核对符号、幅值、采样间隔和分析区间。
2. **双方确定接口。** 用同一份数据给 FPGA 队员，定下点数、格式、窗口、输出缩放和 Linux DMA 负责人；两边可同步开发。
3. **PL 单帧对照。** 对同一输入比较软件参考与 PL 输出，先检查频点，再检查幅值、去直流、窗口及错误返回。
4. **接入语音和界面。** “FFT 分析”完成 HOST4 取点、PL 计算和频谱展示，再确认结果保存与历史查看。
5. **板上验证。** 用已知正弦、方波及偏置信号检查主峰、谐波和直流选项；验证断线、超时、重复提交及取消后的行为。

完整耗时分别记录取点、USB 接收、DMA、PL 计算、绘图/保存。FFT 硬件计算变快，并不等于 USB 取点和整次语音操作按同一倍数加快。
