# 连续记录次数与时间间隔

2026-11-03：将原来仅存在于词表/解析器的连续记录接入当前 Qt 仪表流程。

## 口令

- 连续记录三次数据：默认启动间隔一秒，次数可改为 1—100。
- 连续记录五次数据，时间间隔两秒：次数、间隔分别可改。
- 每隔两秒记录一次，共五次：兼容原有间隔在前的说法。
- 间隔允许 0—60 秒及小数，如“零点五秒”；数值或句子不完整则拒绝执行。

Vosk 使用短语建立 bigram 词表，增加“时间 间隔”、次数和间隔数字组合；次数与间隔仍由完整句子解析和执行层二次校验，不从不完整句子猜数字。

## 行为

1. 点击开始识别，说出完整口令，屏幕展示次数、间隔、两台仪表和采集方式。
2. 点击“确认保存”或说“确认”一次，执行整批。执行前可取消；本次沿用既有提交后等待完成的保存协议，尚未加入执行中的停止按钮。
3. 每轮重新读取万用表当前值，以及示波器 CH1 的峰峰值、频率、有效值。每轮独立归档，在历史中显示第几次/共几次，文件保留批次编号、序号、次数和间隔。
4. 间隔按相邻采集启动时间计算。如果两台仪表读取/落盘耗时超过间隔，则完成后再开始下一轮，不并发、不补赶；不能承诺物理读数严格每秒同步更新。
5. 单台失败/部分成功如实保留，不冒充完整测量。整批完成提示实际归档次数及两台均成功次数。归档中断后同一待确认操作可重试，复用各轮回执，避免重新查询已完成采集或重复写入历史。

本次更新不更改 Qt 二进制、模型、音频解码、声道检测和声音门限。板上已有 Qt 的 saving/confirmed 协议可以接收批次结果；无需重新编译 Ubuntu Qt。

## 文件

- `work/labmate_ui/asr_runtime/text_cli.py`：次数在前、时间间隔在后的完整句式解析。
- `work/labmate_ui/asr_runtime/asr_grammar.py`：可变次数和间隔的语音短语。
- `work/labmate_ui/command_executor.py`：次数/间隔校验、真实双仪表逐次采集、启动间隔调度、回执重用与结果汇总。
- `work/labmate_ui/record_store.py`：逐条归档批次序号及配置。
- `work/labmate_ui/backend.py`：显示正在执行的次数和间隔，沿用手动/语音确认。
- `tools/upload_ui_serial.ps1`：`-BatchRecording` 显式携带这次词表和解析器更新；可与 `-RecordsOnly` 一起部署。
