## SD 卡检查结论

SD 卡是 Windows E:，USB Mass Storage，容量 31,266,439,168 字节，单个 MBR/FAT32 分区。根目录没有 BOOT.BIN、image.ub、boot.scr。之前板端启动日志显示 QSPI 加载启动脚本、内核、设备树和 FPGA，根文件系统是 eMMC 的 mmcblk1p1；本卡是数据卡。不能仅凭卡里增加仪器目录推断启动镜像被替换。

- 卡上原语音工程中，登记清单里的 22 个源码、配置及 libvosk.so 的 SHA256 全部匹配 2026-10-29 基线。
- 46,577,796 字节的原语音 ZIP 包有 94 项，所有项的 CRC 检查通过。
- 排除 Python 缓存和历史备份后，解压目录与原 ZIP 的 57 个文件逐字节一致，包含全部 14 个模型文件。此校验针对 SD 卡，不能扩展为板上 eMMC 模型已校验。
- 两个新增包是 labmate_sa5041_board 和 labmate_sds1202x_board。启动脚本设置进程级 PYTHONPATH 并执行 USB/仪器通信；检查其项目源码和启动、自检脚本，没有发现配置 ES8388、ALSA、FPGA 或系统启动的操作。此检查不证明用户此前没有运行过其他外部命令。
- FOUND.000 中已有 480 个 CHK 碎片文件，共 358,514,688 字节，并有视觉目录的 chkdsk-directory-data 文件。这是历史修复痕迹，不能据此认定语音工程损坏或判断发生时间。
- 本次 `chkdsk E:` 只读扫描报告目录尾部项异常、96 KB 的 3 个可恢复文件/丢失链，并提示文件系统有问题。未加 /F、/R、/X，未回答转换丢失链提示，未修复。输出开头另有 Access is denied；该扫描没有锁定卷，不能当作卡物理损坏的证据。只读行为参见 [Microsoft chkdsk 文档](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/chkdsk)。

此前跑通确有用户反馈。源码保持相同不能证明采样内容和硬件运行状态相同。现有证据不足以将两者差异归因于 SD 卡、通信包或某个寄存器，不再通过重传相同源码来验证这个问题。
