## 2. 先约定每条语音指令的实际行为

| 语音指令 | 现有意图 | 接入后的目标行为 |
| --- | --- | --- |
| 读取数据 | `read` | 从配置的仪器和通道读取并显示，不新增测量历史。 |
| 记录数据 | `record_device` | 确认后读取真实仪器结果，校验并保存，刷新历史。 |
| 连续记录三次数据 | `record_device`，带次数与间隔 | 按约定间隔逐次取得新结果，每条保留采集时间和批次关系；停止阻止后续采集。 |
| 记录波形 / 保存波形 | `save_waveform` | 确认后调用仪器波形接口，保存采样数据及元信息，并生成历史索引；若模块仅支持截图，界面和记录明确写“波形截图”。 |
| 拍一下波形 | `capture_image` | 当前意图表示摄像头拍摄。若需要改为仪器截图，单独约定路由与界面提示。 |
| 记录电压三点三伏 | `record_manual` | 保留人工语音报数的来源，保存口述数值。 |

以上为拟定的执行语义。当前解析器已支持“记录波形”和“保存波形”，通常可复用现有意图。实际语音能否稳定识别这些说法仍需板端测试；设备接入本身不要求调整麦克风或识别模型。

推荐先在配置中指定默认设备和通道。若要同时控制多台仪器，再增加设备选择或语音中的目标参数。

## 4. 返回结果需要包含哪些字段

下面是建议的逻辑字段，具体字段名和存储版本在拿到她的返回样例后统一。

- 共用：本轮请求编号、设备标识、仪器通道、采集时间、成功或失败状态、错误码与错误说明。
- 读数：量名、数值、单位；无法读取时显式返回无效状态；0 是合法测量值。
- 波形：文件或采样数组、点数、时间轴起点和采样间隔、横纵轴单位；若交付原始码，还需换算参数。截图与采样波形使用不同的类型标记。
- 保存结果：记录编号、数据文件位置、元信息位置、保存时间。波形文件与索引均写好后才报告保存完成。
- 来源：仪器型号/标识、USB 直接采集来源、原始语音指令、确认时间；保留模拟数据与人工报数各自的来源。

波形大数组适合保存在独立数据文件中，Qt JSON Lines 通信返回摘要和文件引用。数值编码和单位应按现有校验器做明确转换；不能把一种模块的返回对象不经适配直接交给另一种记录格式。

## 5. 接入时要保证的行为

- 一次请求对应一次执行结果；重试保存复用已取得的数据，防止保存失败后悄悄重新测量。
- 采集时间与保存时间分开记录，连续记录能够识别是否确实取得新一轮结果。若约定读取缓存，明确记录缓存来源与原采集时间。
- USB 会话由一个执行模块管理，避免多个线程或进程同时读写同一仪器造成响应串轮。
- 断线或超时有明确结束状态，界面仍能响应；失败后不生成正常测量记录，不自动以模拟值代替。
- 取消和停止按任务阶段处理：未执行时取消本轮，连续记录时停止后续轮次；已经取得或保存的结果如实反馈。迟到响应按本轮编号核对。
- 语音指令记录与实际测量记录分别标识；用户看到“采集成功”“保存成功”时，应有对应的实际结果。

1. 先由队友在目标板上演示独立读数和波形导出，交付同一版本的源码、环境与样例输出。

4. 接通“记录波形”：核对保存文件、点数、时间轴、幅值和单位；截图则按图片验收。
5. 测试 USB 拔插、仪器未就绪、超时、重复确认、保存失败重试和连续记录停止。
6. 在板上同时运行语音与仪器任务，记录实际耗时，确认界面和取消操作仍能响应。
