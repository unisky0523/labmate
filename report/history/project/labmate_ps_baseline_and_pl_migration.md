# LabMate：PS 基线与 PL 迁移路线

决策日期：2026-10-25（Asia/Shanghai）。这是用户确认的开发顺序，不是竞赛规则新增的要求。

## 已确认的路线

先在目标 Zynq 板的 PS 上跑通语音与图像识别，再根据正确性、分段耗时、数据规模和接口条件，决定哪些任务转到 PL。现阶段不新增或修改 PL 加速逻辑，继续使用厂商现有底层工程；也不连接串口开展调试，直到用户调整当前约定。

语音和图像都列为后续硬件加速候选。具体迁移哪些环节由测量决定，不预设所有环节都要硬件化，也不预设搬到 PL 后一定更快。队伍自研 PL、板级验证、性能和资源证据仍是项目必须补齐的工作。

## 阶段与完成条件

| 阶段 | 当前要完成的内容 | 完成后保留的成果 |
| --- | --- | --- |
| 1. PS 分别跑通 | 语音输入到文字、命令及数值；图像输入到仪表读数或目标识别结果；分别处理失败与异常 | 实际运行代码、依赖与参数、测试原始输入、逐条输出及分段耗时 |
| 2. 最小任务闭环 | 两个流程接入实验助手的必要显示、确认/取消和记录步骤；数据来源清楚，真实与模拟结果可区分 | 目标板 PS 上可复现的软件基线、完整任务演示和对照数据 |
| 3. 选定迁移任务 | 分析热点、并行性、数据通路与资源约束；核对现有厂商工程及接口 | 明确的软硬件划分、接口约定、PS 软件参考和选型依据 |
| 4. PL 实现与验证 | 实现选定 RTL/HLS 模块，验证结果一致性，综合实现并接入实际任务 | 自研硬件源码、仿真、约束、实现报告与板级结果 |
| 5. 同条件对比 | 同板、同数据、同配置下比较 PS 与 PS+PL，计入数据搬运与同步 | 正确性、内核耗时、系统耗时、CPU 负载及 LUT/FF/BRAM/DSP 和时序数据 |

阶段 1 和 2 达到关键功能正确、可重复运行、可测量即可推进下一阶段；不以界面完全美化、语音识别达到百分之百或所有扩展功能完成为前提，避免将 PL 无限推迟。

## PS 阶段现在就要保留的调试条件

1. 保存可重复回放的原始录音和图像，带采样率、声道、像素格式、尺寸、ROI 和来源等必要元数据。调参样本与独立测试样本分开。
2. 划分采集、预处理、识别、后处理、确认与保存几个步骤，分别记录耗时。初始化与首次运行单列，稳定运行耗时另列。
3. 保存需要迁移部分的中间输入输出，使后续可以在没有实时传感器干扰的条件下比较 PS 与 PL。
4. 固定模块输入、输出、数值范围和异常约定。先保持软件模块之间的接口清楚，不为尚未确定的 PL 设计提前绑定某种硬件总线。
5. 保留 PS 实现作为正确性参考和运行回退。以后替换一个计算模块时，尽量复用上层识别、界面和业务逻辑。
6. 硬件材料可先盘点，包括芯片型号、厂商原工程、现有改动、工具版本和启动配置；材料盘点不等于当前开始修改 PL。

现有图像数据源接口或 JSON 文件读取功能，不能直接作为 PS 图像识别已经跑通的证据；需以真实算法、输入与输出确认。现有语音单段识别结果也不能替代整条语音流程的独立测试。

## 候选环节

| 路径 | 后续可评估的任务 | 选型时需要确认 |
| --- | --- | --- |
| 语音 | 定点滤波、降采样、频谱或特征提取等前端计算 | 现有 Vosk 后端可接入的位置、音频格式、CPU 实际耗时，以及搬运是否抵消收益 |
| 图像 | ROI 处理、灰度、阈值、滤波、投影统计或适合的识别子模块 | 当前视频工程可否重建、流接口或内存接口、像素格式，以及任务中的实际收益 |

其中部分语音特征计算位于 Vosk 库内部，不能假定现有 Python 入口可以直接替换；涉及库内部接口或修改时须先评估工作量。完整 Vosk 移植到 PL 不作为当前默认路线。

## 性能对比口径

正式对照的“未使用 FPGA 加速”指同一块 Zynq 板上识别计算采用 PS 软件实现，厂商现有底层逻辑可能仍参与采集或显示。更准确的实验名称是“PS 软件基线”和“PS+自研 PL 加速”，不声称前者整块系统完全没有使用 PL。

PC 可以用于开发和生成正确性参考；PC 耗时不作为 Zynq PS 与 PL 加速比的分母。

建议保留三个版本：

- 初始 PS 版本：记录项目优化前的状态。
- 固定的软件基线：完成必要软件优化后冻结模型、参数、测试数据和高层流程。
- PS+PL 版本：在固定的软件基线上替换选定模块，其余与对照条件一致。

词表调整、减少录音等待、软件算法改变和 PL 加速分别报告，避免把软件收益全部记为 FPGA 贡献。局部加速比与完整任务耗时分别计算；如果硬件化只改善 CPU 占用或吞吐而未缩短单次延迟，也如实报告。
