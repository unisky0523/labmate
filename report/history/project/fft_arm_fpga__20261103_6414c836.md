# FFT 分析：ARM 实现与 FPGA 交接

日期：2026-11-03（北京时间）。本文件为实现交接，取代同日《FFT频谱分析_HOST4与ARM_FPGA接口方案》草案。最后一节记录上板验证结果及未完成项。

## 1. 功能边界

- 继续使用 SDS1202X 与板卡原有 USB **HOST4**，不增加触发线。
- 命令解析支持“FFT分析”“频谱分析”“分析波形”；语音首选“频谱分析”。ARM 经 HOST4 发送停止与波形读取命令，取出 CH1 原始记录，并恢复示波器原触发模式和传输设置。
- ARM 整理输入、调用 FPGA 桥接程序、校验结果、绘制频谱 PNG，并沿用确认保存和历史查询。
- **PL 实现去直流、Hann 加窗、FFT 和功率计算**。目前尚无 FFT bitstream、DMA 驱动或桥接程序；配置 `worker_argv: []` 时仅采样并显示“待 FPGA”，不会生成冒充 FPGA 的频谱。
- 本轮更新的是 Linux ARM 应用，不包含重做 SD 卡、重刷系统或烧写 FPGA bitstream。

```text
语音 → ARM 后台 → HOST4 USB → SDS1202X CH1
                    ↓ 采样记录 + 本帧标定
             input.i16le / request.json
                    ↓ FPGA 桥接程序（待交付）
                DMA → PL FFT → DMA
                    ↓ power.u64le / response.json
            ARM 幅值标定 → Qt 频谱图 → 确认保存 → 历史记录
```

## 3. HOST4 采样约定

绑定身份：`SIGLENT,SDS1202X,SDS1XDC4163410`；USB VID/PID `f4ec:ee3a`；本板物理路由 `1-1.4`；资源 `USB0::62700::60986::SDS1XDC4163410::0::INSTR`。程序检查设备、序列号及路由，不能将 HOST4 理解成 `/dev/usbtmc4`。

执行顺序：

1. 查询 `*IDN?`、`TRMD?`、`WFSU?`，保存原配置。
2. 发送 `STOP` 并回读停止状态。
3. 查询 `SARA?`、`TDIV?`、`C1:VDIV?`、`C1:OFST?`。
4. 设置 `WFSU SP,1,NP,0,FP,0`，读取 `C1:WF? DAT2` 的完整二进制记录。
5. 按 `#<位数><字节长度>` 解块；载荷内的换行、零字节均为数据；检查通道前缀和尾部。
6. 无论读数成功与否，恢复原 `WFSU` 与 `TRMD`，回读触发模式；恢复失败独立报错。

单次布防 `SINGLE` 和非零分段号 `SN` 当前拒绝执行，避免重新布防或误读分段记录。应用内普通读数、截图和 FFT 共用调度锁；外部独立调试程序不得同时占用示波器。

原始编码为有符号 8 位，接收字节 `b>=128` 时 `code=b-256`，否则 `code=b`。本机使用的标定为：

```text
V = code × (VDIV / 25) - OFST
dt = 1 / SARA
```

不额外重复乘探头倍率。若修改探头/量程或改用其他机型，需重新与实际已知幅度信号核对标定。本轮不改变发生器幅度、输出开关、扫频或示波器时基。

旧固件 `1.1.2.13 R5` 本轮对 `SANU?` 查询超时并使 USBTMC 会话堵塞，运行路径不使用该命令。恢复用的是 USBTMC 接口 CLEAR（INITIATE_CLEAR=5、CHECK_CLEAR_STATUS=6），不是 `*RST`；现场脚本和记录保存在验证目录。不要在正常业务中盲目设备复位或反复发送不支持的命令。

本机另有已实测的返回差异：发送 `C1:WF? DAT2` 后，前缀为 `C1:WF ALL,#9...`，载荷为 700000 个模拟采样字节，无 WAVEDESC。仅对这台已绑定的 `1.1.2.13 R5` 固件启用 ALL 兼容，拒绝含 WAVEDESC 或长度与 `SARA×TDIV×14` 不一致的返回；不能推广为任意 ALL 响应都可当采样。

## 4. 首版取样范围和分辨率限制

当前默认 N=4096，可配置为 256～65536 的 2 的整数次幂。程序保存完整原始记录，**取记录中央连续 N 点**作为一次 FFT 输入，未实现抗混叠降采样、整屏压缩或自动时基调整。`segment_start` 为原记录中从零开始的样本索引。

```text
Fs = 1/dt
频点间距 df = Fs/N
分析时长 T = N × dt
横轴 f[k] = k × df，k=0…N/2
```

例如 Fs=1 GSa/s、N=4096 时，T=4.096 µs、df=244140.625 Hz，不能解析 1 kHz 细节，也不能称为整屏频谱。提高 N、合适的采样时基，或设计有抗混叠滤波的抽取模块后再扩展；不能简单跳点并沿用原采样间隔。若需要整屏分析，应作为双方下一项明确任务。

## 5. 桥接程序调用接口（已在 ARM 中实现）

FPGA 同学需交付可在当前 ARMv7 Linux 上运行的可执行桥接程序。可执行文件、驱动、设备树、bitstream、DMA 和寄存器地址必须与同一个硬件版本匹配。

在 `instruments.json` 中设置，例如：

```json
"fft": {
  "fft_size": 4096,
  "worker_argv": ["/home/root/labmate_ui_test/fpga_fft_worker"],
  "renderer": "/home/root/labmate_ui_test/labassistant"
}
```

ARM 实际调用，不经过 shell：

```text
/home/root/labmate_ui_test/fpga_fft_worker --request <任务目录>/request.json --response <任务目录>/response.json
```

同一时间提交一个任务。进程退出码 0 且已生成完整响应才算成功。桥接上限 60 秒；当前 Qt 等待操作上限也是 60 秒，**采样、计算与绘图总耗时必须控制在 60 秒内**，首版桥接建议 10 秒内完成。若硬件初始化/大记录超过此值，双方先统一 UI 与后台超时，再重新编译部署。取消后后台不展示或保存迟到结果；取点进程保留恢复示波器的时间。

桥接程序先检查协议、长度和 SHA256，再执行 DMA。响应采用临时文件写完后原子重命名；仅在最后发布 `response.json`。不允许返回上个任务的缓存频谱。

## 6. 输入文件与定点算法（协议 labmate.fft.v1）

任务目录包含：

| 文件 | 格式与含义 |
| --- | --- |
| `scope_codes.i8` | 完整原始有符号 8 位采样 |
| `capture.json` | 采样率、量程、标定、身份、原始 SHA256 等 |
| `scope_evidence.json` | 实际命令、响应及恢复错误 |
| `input.i16le` | N 个小端 int16，每点 `x=code×128`；N=4096 时 8192 字节 |
| `window.q15le` | N 个小端 int16，周期 Hann Q15 系数；8192 字节 |
| `request.json` | 协议、任务号、输入与系数校验、物理标定 |

必须遵循：

```text
w[i] = min(32767, floor((0.5-0.5*cos(2πi/N))*32768 + 0.5))
dc = trunc_toward_zero(sum(x)/N)
y[i] = arithmetic_right_shift((x[i]-dc)*w[i], 15)
X[k] = FFT(y)，forward，负指数，未归一化
```

均值累加器及乘法中间量需足够位宽。负数右移是算术右移，不能改为向零取整。窗顶饱和到 32767；周期窗分母为 N，不能换成 N-1。去直流和加窗在 PL/FPGA 桥接所控制的硬件路径实现，ARM 不预先执行这两步；系数文件由 ARM 生成。

请求的固定字段：

```json
{
  "protocol": "labmate.fft.v1",
  "request_id": "本次任务号，原样回传",
  "fft_size": 4096,
  "input_file": "input.i16le",
  "input_dtype": "int16_le",
  "input_sha256": "输入文件SHA256",
  "window_file": "window.q15le",
  "window_sha256": "系数文件SHA256",
  "window": "hann_periodic_q15",
  "remove_dc": true,
  "dc_rounding": "truncate_toward_zero",
  "window_rounding": "arithmetic_shift_right_15",
  "output_kind": "power_u64_le",
  "output_order": "natural",
  "bin_count": 2049,
  "response_file": "response.json",
  "power_file": "power.u64le"
}
```

实际 JSON 还包含 `sample_interval_s`、`volts_per_input_lsb=(VDIV/25)/128`、`volts_offset=-OFST`、`window_sum=sum(w)/32768`、`capture`、`segment_start`、`segment_count`。FPGA 不需要解释电压/时间参数，ARM 用它们绘图；必须与对应任务一起保留。

## 7. 返回文件

`power.u64le`：小端无符号 64 位，k=0…N/2 **自然频率顺序**，每点功率 Re²+Im²；N=4096 时共 2049 点、16392 字节。不接受浮点、幅度数组、交织复数或位反序冒充这个格式。

`response.json` 的字段与类型：

```json
{
  "protocol": "labmate.fft.v1",
  "request_id": "原请求的任务号",
  "input_sha256": "原请求的输入SHA256",
  "fft_size": 4096,
  "bin_count": 2049,
  "output_kind": "power_u64_le",
  "output_order": "natural",
  "power_file": "power.u64le",
  "power_sha256": "实际功率文件SHA256",
  "status": "complete",
  "overflow": false,
  "backend": "fpga",
  "fft_right_shift": 0,
  "power_right_shift": 0
}
```

两个 shift 为 0～64 的整数，必须返回真实缩放：`fft_right_shift=s` 表示输出复数约为未缩放 FFT 的 `2^-s`；`power_right_shift=p` 表示计算平方和后再右移 p 位。固定缩放方案和块浮点的 `BLK_EXP` 都须转换为这个定义，不能遗漏 IP 隐含比例。

ARM 标定：

```text
A[k] = sqrt(P[k]) × 2^s × 2^(p/2) × volts_per_input_lsb / window_sum
对 k=1…N/2-1 再乘 2；DC 与 Nyquist 不乘 2
单位：单边幅度 Vpeak
```

主峰当前取非 DC 最大频点，无频率插值；不是任意信号的精确频率测量，也不是 Vrms、dBV 或 PSD。

身份、N、长度、顺序、数值溢出、输入/输出 SHA256 或状态不符时，ARM 拒绝绘图和保存成功结果。桥接失败应返回非零退出码并写清 stderr；检测到溢出不得标 `overflow:false`。

## 8. FPGA 同学还需交付

1. Zynq-7010 可用的 PL 工程和 bitstream：去直流、窗乘法、FFT、自然顺序半谱功率及溢出状态。
2. DMA 流格式：AXI 数据位宽、实虚部布局、符号扩展、每拍点数、TLAST、收发字节数及缓存对齐。
3. AXI4-Lite 地址和寄存器定义、启动/忙/完成/错误/复位、中断方式、超时恢复。
4. 与当前 Linux 5.4.0-xilinx-v2020.2 匹配的设备树、驱动/设备节点及部署方式。
5. ARMv7 hard-float 桥接程序及源码，遵守上面的文件契约；DMA 缓冲分配、物理地址和缓存同步由驱动管理，不把 Python 虚拟地址直接交给 DMA。
6. 先准备接收，再启动发送；FFT 完整输出帧必须正确消费，即使应用只需要 N/2+1 点。记录 IP 数值模式、缩放表和溢出覆盖范围。

本交接未编造 DMA 地址、寄存器偏移或现成设备节点；它们须来自实际硬件设计。
