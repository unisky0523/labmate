## 3. 完整运行链路

```text
用户在板端串口执行 sh ./run_ui_voice.sh
  → 检查模型、库、依赖、音频占用，设置环境变量
  → run_ui_test.sh 临时停止厂商桌面，配置 framebuffer 和触摸
  → 启动 ARM Qt 程序 labassistant
  → Qt 的 QProcess 启动 python3 -u 和外置 backend.py
  → backend.py 按 LABMATE_ASR_ROOT 选择真实模式
  → asr_adapter.BoardRecognizer.prepare
      → Vosk 模型加载一次
      → board_listen.ContinuousMicrophone 初始化持续音频流
  → 用户点开始，Qt 发送 JSON start 请求
  → 等待本轮完整语音，送 asr_cli.analyze 与命令词表解析
  → Python 把文字、解析结果或拒绝原因通过 JSONL 返回 Qt
  → 用户确认后，当前 record_store.py 保存结果；历史页读取展示
  → 用户关闭助手，释放音频资源并恢复厂商桌面
```

模型和采集对象在同一次打开期间复用。空闲音频不会直接作为下一次按钮操作的结果。初始化不是每次按开始都重新执行。

## 6. 正常启动与说话步骤：直接照这个操作

**位置：板端串口终端，提示符是 `root@ATK-ZYNQ:...#`。**

先关闭屏幕上已有助手，等待串口提示符回来，然后执行：

```sh
cd /home/root/labmate_ui_test
sh ./run_ui_voice.sh
```

当前脚本预期打印 `Backend imports OK`、板卡时间，再打开页面。等到模型和麦克风就绪：

1. 进入语音识别页，点“开始识别”。
2. 等出现“现在请说话”再说一句，例如“记录电压三点三伏”。
3. 说完保持安静约 0.8 秒，等显示实际文字及理解结果。
4. 有拒绝原因时先看原因，不把它当作已经接受的指令。
5. 结果正确再点确认保存，查看历史中的内容、数值和时间。
6. 再试“记录电流十毫安”；取消一轮则不应新增记录。
7. 点“关闭助手”退出；启动脚本返回后，厂商桌面应恢复。

助手占用当前串口前台期间，终端不出现新的 root 提示符是正常现象，不表示卡死。先在屏幕关闭助手，才在同一终端执行其他检查命令。

### 最容易混淆的启动方式

| 操作 | 实际含义 |
| --- | --- |
| 新终端直接 `./labassistant` | 不保证具备 framebuffer、触摸或真实识别环境 |
| 新终端只执行 `sh ./run_ui_test.sh` | 配置显示，但未自行选择真实语音；没有继承真实环境时会进入模拟模式 |
| `sh ./run_ui_voice.sh` | 配齐真实语音环境，再调用显示启动器，是当前应使用的入口 |
| 直接 `python3 backend.py` | 不是完整 GUI 启动；无真实模式环境时为模拟，且等待 JSON 协议输入 |

`run_ui_test.sh` 若恰好继承了旧环境也可能进入真实模式，因此不要仅凭脚本名字推断；正常使用统一走 `run_ui_voice.sh`。

## 8. 当时用的音频和识别参数

以下参数本次只记录，不建议直接修改：

| 项目 | 原版/当前基线 |
| --- | --- |
| 录音设备 | `hw:0,1` |
| 静音播放保活设备 | `default` |
| 原生采样 | 44100 Hz、双声道、S24_LE |
| PCM 解码 | 每个 4 字节槽的低 24 位，小端有符号数 |
| 识别声道 | 左声道，索引 0 |
| Vosk 输入 | 转换为 16000 Hz 单声道 |
| 分句帧 | 20 ms |
| 能量门限 | 0.01，去均值后的帧 RMS |
| 句尾静音 | 0.8 秒 |
| 单句上限 | 12 秒，超长整句丢弃 |
| 点击开始后的等待上限 | 25 秒，等待完整分句 |
| 词置信度筛查 | 0.45 |
| 中文模型 | vosk-model-small-cn-0.22 |
| 词表模式 | asr_grammar.GRAMMAR_JSON，command_grammar=True |

持续音频启动顺序来自队友验证过的链路：先 aplay 静音保活 → 再 arecord → 配置 ES8388 → 丢弃启动期数据 → 持续分句。

底层自动启动的核心音频命令相当于：

```sh
aplay -q -D default -t raw -f S24_LE -r 44100 -c 2 /dev/zero
arecord -q -D hw:0,1 -t raw -f S24_LE -r 44100 -c 2
```

**这两行只用于解释源码，不要在 GUI 正在运行时手动再执行。** 它们由 Python 管理子进程，arecord 数据走管道，不是默认保存到磁盘。

自动 ES8388 设置为 I²C 总线 0、地址 0x10，寄存器 `0x0a=0x00`、`0x03=0x09`、`0x0d=0x03`；随后设置 `ALC Capture Function=Off`、`Left Channel=4`、`Right Channel=4`。这些是已存在的程序动作，不是本次新增修复建议。

当前源码 `CAPTURE_WARMUP_SECONDS=3`，加上先启动播放流的等待，采集初始化约有数秒，另有模型加载时间。**此前讨论过减少约 4 秒启动时间，但不能据此认为预热已经取消或改成 1 秒。** 同一次运行后续识别复用模型和采集流。

上传器现在已经改进，与初次部署时行为不同：

| 当前参数 | 作用 |
| --- | --- |
| `-RealAsr` | 上传当前界面/后台等，默认保留板上适配器和 asr_runtime |
| `-RealAsr -RecordsOnly` | 只更新记录后台、存储模块和语音启动脚本，不传 Qt 二进制或语音源码 |
| `-RealAsr -InstallAsrRuntime` | 明确用于需要安装完整语音副本的场景，会传适配器及 asr_runtime；不能与 RecordsOnly/RestoreVoiceBaseline 混用 |

| `-PrepareOnly` | 只在 Windows 打包检查，不打开串口 |

接收器在 `/home/root/labmate_ui_test` 更新文件，同名原文件备份为 `.bak.<板端时间戳>_<进程号>`，不应删除这些备份。旧版上传器曾默认发送语音源码，因此本地文件不变不等于历史上板端文件从未被覆盖。

修改 C++/嵌入资源通常要重新交叉编译；仅修外置 Python 和启动脚本、且与 V2 协议兼容时不必重编译。

## 10. “语音突然没了”目前究竟查到了哪里

按 2026-11-01 已有本地排查记录整理，避免下个对话重复走弯路：
