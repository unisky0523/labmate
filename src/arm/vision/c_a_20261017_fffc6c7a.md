# LabMate C 视觉模块交接给 A

首次编写：2026-10-17；更新：2026-10-18。适用设备：Keysight InfiniiVision DSO-X 2012A 正面屏幕照片；目标板：Zynq-7010 Linux（ARMv7 hard-float）。A 负责板端系统与实测，C 负责视觉程序及匹配目标系统的推理程序构建。

## 交付文件与状态

当前修正版：`c_vision_lite/generated/labmate_lite_image_reader_board_v2.zip`。旧的 `labmate_lite_image_reader_board.zip` 和 `labmate_lite_arm_probe.zip` 均不要当作本次交付包。v2 含 ARM `smoke_infer`、Paddle-Lite 检测/识别 `.nb` 模型、动态库、Python 流程、设备配置、测量页及光标页样图，还包含 `smoke_infer.cc`、`CMakeLists.txt`、`README_IMAGE_BOARD.txt` 和 `BUILD_BOARD.txt`。`board_manifest.json` 记录包内文件哈希。v2 ZIP 的 SHA-256：

```text
3e7099b248b966769ac06bf55e5f21035f5065e52111551c9650ac2acff57803
```

**重要：v2 仍不是可直接在审阅过的出厂 Linux 上运行的成品。** 附带的 `smoke_infer` 由较新的交叉编译环境生成，外部审阅指出它要求的 glibc/libstdc++ 版本高于出厂 rootfs；必须先按 A 实际板端系统的 SDK/sysroot 重编译并替换，不能通过复制新 `libc.so.6` 到板上解决。C 提供源码和构建步骤；A 需提供实际系统版本或匹配的 SDK/sysroot，双方据此完成编译与上板测试。模型与现有包的完整性通过检查，但新二进制、依赖、内存和摄像头尚未在实体板验证。32 GB SD 卡容量不能替代 512 MB 运行内存。

## 功能边界

- 输入完整 JPEG/PNG，自动定位屏幕与右侧面板；不需要人工指定裁剪坐标。也可以用 `--camera` 采集**单帧**，不是实时预览。
- 测量页：读取可辨认的测量名称、通道、数值和单位；行数按画面动态处理。识别不确定时返回无效结果，不能作为正式记录。
- 光标页：读取右侧栏的 `ΔX`、`1/ΔX`、`ΔY` 及对应数值/单位。底部设置菜单的 `X1/X2/Y1/Y2` 尚未解析；其他光标布局未验证。
- 输出同一格式的 `reading.json`：`request_id` 用于和 B 的语音指令关联，`measurements` 是逐项结果。多项读数时，顶层 `value: null` 是正常的；请以 `measurements` 为准。顶层 `valid` 仅在各项均通过校验时为 `true`。
- 当前适配这台 Keysight 示波器；其他型号、严重反光/模糊、屏幕不完整的图片不在已验证范围。


## A 的首次上板步骤

先把 v2 ZIP 拷到板端 Linux 并解压，在**解压目录**检查系统。板端 Python 需要能导入 `numpy`、`cv2`、`pyclipper`；不要求安装 Python 版 PaddleOCR。不要直接复制 Windows 虚拟环境。`libgomp.so.1` 也可能需要按板端系统补齐。

```bash
uname -m
python3 --version
getconf GNU_LIBC_VERSION
python3 -c 'import numpy, cv2, pyclipper; print(numpy.__version__, cv2.__version__)'
free -m
ldd ./smoke_infer
ldd ./libpaddle_light_api_shared.so
```

若 `ldd` 显示缺库或版本不符，**停止识别测试**。C 使用 A 所用系统的 SDK/sysroot 按包内 `BUILD_BOARD.txt` 重编译 `smoke_infer`，替换旧二进制；A 安装或提供匹配的 Python 依赖与运行库。完成后再次检查 `ldd`，再运行：

```bash
chmod +x smoke_infer
export LD_LIBRARY_PATH="$PWD${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
python3 -m c_vision_lite.board_reader --image sample.jpg --bundle . --out runs
python3 -m c_vision_lite.board_reader --image sample_cursor.jpg --bundle . --out runs
```

每次运行会在 `runs/时间_请求ID/` 下保存原图、调试图、OCR 证据和 `reading.json`。程序也在终端打印 JSON。退出码 `2` 表示该次结果无效，需查看 `error_code`；不一定是程序崩溃。若缺 Python 模块，导入阶段可能只有 traceback，没有 JSON。

包内两张样图跑通后，再试 A 在板上取得的照片：

```bash
python3 -m c_vision_lite.board_reader --image /path/to/photo.jpg --bundle . --out runs
```

OV5640 如已在 Linux 中提供 `/dev/video0`，可尝试单帧采集；它是否支持 OpenCV `VideoCapture`、所需分辨率和对焦质量，必须现场确认：

```bash
python3 -m c_vision_lite.board_reader --camera /dev/video0 --bundle . --out runs
```

B 侧以后发出“记录”指令时，可调用同一命令并传入 `--request-id`；目前没有直接集成 B 的进程或消息总线。

## 验收与反馈

1. 测量页、光标页两张包内样图都能在板上产生 `reading.json`，逐项核对 `label`、`channel`、`value`、`unit`、`valid`，不要只看顶层 `valid`。
2. 用同一张照片在电脑端和板端分别运行，比较每一项结果；这一步完成前，不能声称板端识别率与电脑端一致。电脑端当前两张已有光标照片成功读出右侧三项，但未构成板端准确率测试。
3. 测试 OV5640 的图像清晰度、单帧耗时和连续多次运行时的可用内存。不要为了让程序能启动就直接降低 `--detector-size` 并沿用原准确率结论；改变尺寸后要重新比对读数。
4. 出错请回传完整终端输出、对应的 `reading.json` 或 `failure_*.json`、原图、`free -m`、`ldd` 结果。若进程被系统杀死，再提供 `dmesg` 中的 OOM 相关记录。C 据实测结果修运行库、内存或识别问题。

电脑端源码入口为 `c_vision_paddle/reader.py`，板端入口为 `c_vision_lite/board_reader.py`。旧文档 `Paddle-Lite板端可行性与交付清单.md` 记录的是 10 月 15 日尚未完成模型转换时的状态，不应代替本次交接说明。
