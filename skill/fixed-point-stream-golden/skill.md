# 定点流式 RTL 黄金参考

把接口契约写在算法前面。先确定输入输出位宽、符号位和通道号，再确定定点缩放、舍入、饱和及复位行为。按 `valid && ready` 的握手顺序对比，不把时钟周期直接当作样本编号。

## 快速复测

在 `skill/fixed-point-stream-golden/` 下运行，Python 3 负责调度，仿真用 Vivado 2020.2 的 XSim。`--vivado-bin` 改为本机 Vivado 的 `bin` 目录。脚本在临时目录运行，输出四条 `PASS BYPASS` 记录，每条包含 6000 个样本。

```powershell
python scripts/run_xsim.py --vivado-bin 'D:/Xilinx/Vivado/2020.2/bin'
```

`rtl/` 是实际使用的 Verilog 和系数，`tests/tb_frontend.sv` 检查反压时的输出稳定性、样本计数、声道和输出值。`tests/generate.py` 是独立整数黄金模型及向量生成器。默认回归直接读取随包向量。要改变滤波器时，在技能目录的工作副本中修改生成器，安装 NumPy 和 SciPy 后执行 `python tests/generate.py`。该命令会覆盖工作副本中的系数和向量。确认参考输出的修改源于明确的算法契约，再运行仿真。

## 复用流程

1. 为新算法保留参考模型、输入向量、预期输出和测试台四类文件。将 `generate.py` 中的算术改成独立的软件定义，覆盖脉冲、极值、随机值以及跨通道交替。算法改动和测试台改动分开审查，避免用 RTL 的输出回填期望值。
2. 按握手接收的顺序逐字比对。对输出随机施加反压，在停顿期间检查 `valid`、数据和元数据稳定。至少测试一次处理中复位和复位后重新播放。纯旁路应逐位一致。
3. 记录首次差异的样本索引、通道和实际／预期字。先用小向量定位符号扩展、移位、舍入和饱和，再运行完整回归。修改握手或缓存后重新检查样本计数。

### 提示词模板

> 根据我提供的流接口和定点算法，先写逐样本契约，然后实现独立 Python 整数参考与 RTL 测试台。输入格式为 [位宽和元数据]，舍入及饱和规则为 [规则]。沿用 ready/valid 的实际握手顺序，覆盖反压和复位。输出可执行复测命令、首个失配诊断、已执行结果及板级未验证项。预期值由参考模型生成。

## 来自项目的验证和边界

样例为 44.1 kHz 音频的 127 抽头 FIR，系数有 17 个小数位。24 位样本、通道标签、无效标志和奇偶校验沿用原项目格式。原工程处理逐通道历史，测试特意覆盖声道交替、无效帧和复位中断。最初只在主机验证算法不足以覆盖这些流协议行为，因此提炼成逐样本和握手联合检查。

本次从原项目提取后，用 XSim 2020.2 重新运行。滤波和旁路各两轮，每轮 6000 字，全部通过。`filter_metrics.json` 是系数量化模型的频响数据，语音识别正确率和端到端耗时另行测量。迁移到不同采样布局、通道数、滤波目标、时钟域或更高输入吞吐时，应重新核对算法格式、最坏处理周期、CDC 和实际综合资源。
